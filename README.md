# Codex Remote MCP

将本机 **Codex** 封装为远程 MCP 服务的个人双 Agent 协作桥（支持 Windows / macOS）。项目目前面向 **Gemini 网页端** 做了深度适配，同时也适用于其他支持远程 MCP 的网页端 AI、桌面客户端或 CLI Agent。

下文均以 Gemini 为例：由上游 AI 负责需求梳理、方案设计与体验把控，本机 Codex 负责核查仓库、修改代码并运行验证，并与 **Codex 桌面端** 保持同会话协同。

## 核心能力

- **远程操作本机仓库**<br>
  在 Gemini 网页端调用本机 Codex 读取代码、修改文件、运行测试，或发起不留会话记录的临时只读调研。

- **方案讨论与代码事实评审**<br>
  与 Gemini 讨论架构或改动方案后，可派发只读评审基于本地代码核对事实、边界条件与风险，再由 Gemini 吸收事实纠偏并整合取舍建议，在实施前消除方案幻觉。

- **与桌面端同会话协同**<br>
  无论会话建在 Gemini 还是桌面端，桌面端打开页面时 Gemini 仍可通过队列续接原会话；桌面端同步刷新当前进展，可随时在桌面端打断或补充引导。

- **自动上下文剪枝与分叉**<br>
  同一会话出现偏题、废弃方案或切换子任务时，Gemini 会自动做上下文剪枝：回溯定位最合适的已完成轮次并从该处 fork，将后续仍有效的约束带入新分支继续任务，无需手动管理分支。

- **跨项目历史反查**<br>
  仅提供模糊线索或 Issue 编号时，可通过一次性只读探针跨项目检索本机历史会话与记忆，定位对应线程后按需切片读取正文。

## 其余特性

- **按任务选档**：按探查、编码、评审、深度架构分别匹配对应模型与推理强度，可在配置中自定义。
- **热加载与远程自重启**：修改协作规则、模型档位或项目白名单后热加载生效；升级代码后支持远程重启桥接，隔离预检未通过时旧服务保持在线。
- **分层安全边界**：仅监听本机回环地址，通过 OAuth 一次性短码完成绑定；默认只读与工作区沙箱隔离，终端联网按需开启，全权限模式仅限白名单项目且须当轮授权。
- **长任务与多模态支持**：支持异步长轮询、幂等防重复执行，以及读取仓库内本地图片。

## 一、上手前准备与注意事项

### 1. 你需要准备什么
- **本机环境**：一台 Windows 或 macOS 电脑（需 Node.js 22.16+ 与独立 `@openai/codex` CLI，部署时 Codex 会自动检查并引导安装）；如同时安装 Codex 桌面端，可在桌面端实时查看进展并随时打断或引导。
- **公网 HTTPS 入口**（四选一，部署时 Codex 会引导配置）：
  - **有自有域名** → 推荐 **Cloudflare Named Tunnel**（免费、域名固定、最稳定）。
  - **没有域名** → 首选 **Tailscale Funnel**（免费获得固定 `*.ts.net` 网址）。
  - **有自己的 VPS / 反代** → 直接将 HTTPS 流量反代到本机端口（默认 `9088`）。
  - **只想先试用 10 分钟** → 可用 **Cloudflare Quick Tunnel**（免账号域名，但每次重启会换网址导致绑定失效）。

### 2. Gemini 端隐形门槛与使用提醒
- **找不到 Custom Apps 入口**：Gemini 自定义应用对账号、地区与语言有平台限制，若界面里看不到入口，直接访问 [https://gemini.google.com/usage?hl=en](https://gemini.google.com/usage?hl=en) 确认当前账号是否可用。
- **普通对话模式 vs 任务模式（实测优缺点对比）**：

  | 模式 | 优点 | 缺点 |
  |---|---|---|
  | **普通对话模式** | 可自由选择模型的思考强度 | 额度消耗较快；单轮工具调用次数较少，Codex 执行较久时可能需要手动催促再次查询进度 |
  | **任务模式** | 连续调用流畅、可持续等待长任务完成，额度消耗相对少很多 | 无法选择思考强度，只能使用默认强度（猜测约为 `low`） |
- **网页上传文件边界**：直接在 Gemini 网页端上传的图片、PDF 等文件无法自动写入你本地磁盘；如果需要 Codex 修改原件，请先把文件放进本地项目目录再告知路径。

## 二、快速开始（交给本机 Codex 部署）

无需手动克隆或翻阅文档，直接把下面这句话发给你本机的 Codex：

```text
请把 https://github.com/pernalin9/codex-remote-mcp.git 克隆到合适的本地目录（如目录已存在先问我），然后读取仓库里的 DEPLOY_PROMPT.md，按其中的步骤一步步引导我完成部署。
```

### 检查更新与排查问题

后续想检查新版本、同步新发现的环境避坑项，或遇到连接异常需要排障时，直接把下面这句话发给本机 Codex：

```text
请查看 GitHub 上 pernalin9/codex-remote-mcp 最新的 VERSION_MANUAL.md，对比我本机的 codex-remote-mcp 版本并核对已知问题，如有更新或需要注意的环境坑点请提示我并引导处理。
```

## 三、常用运维命令

```bash
npm run ctl -- start           # 后台启动本地桥接服务
npm run ctl -- stop            # 停止本地服务
npm run ctl -- restart         # 重启本地服务（修改 .env 后使用）
npm run ctl -- status          # 查看运行状态与健康检查
npm run ctl -- logs            # 查看最近服务日志
npm run doctor                 # 环境体检（Node、CLI、登录态、端口与配置）
npm run repo -- list           # 管理暴露的本地项目白名单（list / add / remove）
```
